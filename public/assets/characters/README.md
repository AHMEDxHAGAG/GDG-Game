# Character artwork

The five production pirate cutouts live here. Do not rename them: the filenames **are**
the `TrackId`s, and `tools/generate-artwork-manifest.mjs` derives
`src/generated/artwork-manifest.ts` from them.

```text
public/assets/characters/
  software-engineering.webp     # Software Engineering — red coat, gear tricorne, tool belt, code scroll
  ai.webp                       # Artificial Intelligence — blue coat, goggles, glowing AI orb
  web-development.webp          # Web Development — orange/black coat, plumed tricorne (landing hero, centre)
  data-science.webp             # Data Science — violet coat, wide-brim hat, holographic chart tablet
  cybersecurity.webp            # Cybersecurity — masked stealth pirate, glowing green code sheet
```

Only the WebP derivatives are published here. The untouched 1024×1536 PNG originals
live in `assests/Characters/` and are **not** copied into `public/`: they were
byte-identical duplicates, nothing ever requested them (`tools/prepare-ui-assets.mjs`
resizes straight from `assests/`), and they cost ~9 MB in every deployment.

## Source

## Verified properties

These were measured by decoding the PNG alpha channel, not inferred from file names:

- **Genuinely transparent.** All four corners are alpha 0. Roughly 45–57 % of each
  canvas is fully transparent, plus a 3–5 % soft-glow band around the figure.
- **2:3 portrait, not 1:1.** Older notes in this folder asked for 1:1; the supplied art
  is 1024×1536. Layout code must use these real intrinsic dimensions.
- **No baked text, logos or QR codes.** Nothing in the image carries copy.

## Notes

- Responsive WebP derivatives, regenerated by `npm run assets:prepare`:
  `<track>.webp` (768×1152), `<track>-512.webp`, and `<track>-256.webp`. `CharacterArtwork`
  serves these through a `srcSet` with intrinsic `width`/`height`, so the browser reserves
  the right box and there is no layout shift.
- Sized for real phones, not a DPR-1 browser: the 256w tier is what a ~360 px screen
  actually selects at DPR 2–3. Do not "optimise" these further without checking the
  rendered CSS size first.
- Served as plain `<img>` with explicit `width`/`height`, not through `next/image`:
  `html-to-image` re-fetches image URLs during PNG export and `_next/image` optimisations
  have been a recurring source of export flakiness.
- If a file goes missing, `CharacterArtwork` falls back to the designed ink placeholder
  (track colour + emblem + silhouette) via `hasArtwork()`, so the experience stays
  reviewable. It never requests a path that is not on disk.
